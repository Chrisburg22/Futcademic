# AGENTS.md

Futcademic — multi-tenant football academy management system (Spanish-language product, Spanish comments/UI).

## Repo layout: `backend/` and `mobile/` are separate git repos

- This root repo tracks only: `web/`, `landing/`, `docs/`, `migrations/`, `schema.sql`, `mineria/`, `compartir/`, `scripts/`.
- Current focus: **`backend/`, `web/`, and `landing/` only**. `mobile/` is a separate Expo repo and out of scope for now; don't mirror changes there unless asked.
- `backend/` and `mobile/` are **independent git repos** (listed in root `.gitignore`, remotes `futcademic-backend` / `futcademic-mobile`). Root `git status` will not show their changes; commit and push them from inside their own directory.
- No workspaces, no root task runner, no CI. Install and run each workspace independently.
- Deploys: `web/` → Vercel (Next.js, auto-detected — no `vercel.json`), `backend/` → Render (`futcademic-backend.onrender.com`), `landing/` → separate static host.

## Commands

### web/ (Next.js 16 App Router + React 19 admin panel)
```bash
cd web && npm install   # npm: package-lock.json is the tracked lockfile
npm run dev        # http://localhost:5173 (next dev -p 5173)
npm run build      # next build (typecheck included)
npm run start      # serve production build on 5173
npm run test:e2e   # Playwright, mocked backend, auto-starts dev on 127.0.0.1:5173
npx playwright test e2e/fase2.spec.ts -g "part of a test name"   # single test
ALLOW_PROD_SMOKE=yes npm run test:smoke # ⚠️ hits production and creates real academies
```
`web/AGENTS.md` is generated by `next dev` and points to the bundled Next docs in `node_modules/next/dist/docs/`; read those before using Next APIs you are unsure about.

### backend/ (Express + TypeScript)
```bash
cd backend && npm install
npm run dev          # ts-node api/index.ts (PORT or 3000)
npm test             # jest, all of api/__tests__
npx jest api/__tests__/auth.test.ts -t "test name"   # single test
npm run routes:dump  # regenerate api-contract.json
npm run build        # tsc → dist/
```
`dist/` is **committed** in the backend repo. After changing `api/**`, run `npm run build` and commit `dist/` along with the source change.

### landing/ (Astro, static)
```bash
cd landing && npm install
npm run dev        # http://localhost:4321
npm run build
npm run capturas   # regenerate public/capturas/*.png and og.png
```
Read `landing/README.md` and `landing/AGENTS.md` before touching it: all copy lives in `src/consts.ts`, and the PRD rule is that no claim may appear without a verified backing screen.
`capturas/` and `demo/` levantan `../web` con `next build && next start` en el puerto 5174 (Supabase/API stub), así que necesitan que `web/` compile; regeneran PNGs y el MP4 versionados en `landing/public/`.

## Bóveda Obsidian (`vault/`)

`vault/` es una bóveda Obsidian con el mapa del proyecto para localizar código sin grepear todo el repo.

- Empieza en `vault/00-Inicio/Boveda Futcademic.md`; para agentes, `vault/08-Agentes/Protocolo de busqueda.md`.
- Las notas con `tipo: generado` (rutas de API, tablas, rutas web, hooks, índice) se construyen desde el código: **no editarlas a mano**.
- Tras cambiar rutas, esquema, pantallas o hooks: `python3 scripts/vault/vault.py generar`.
- Antes de cerrar un cambio: `python3 scripts/vault/vault.py verificar` (enlaces, fuentes y notas obsoletas).
- Si una nota contradice al código, gana el código: corrige la nota en el mismo cambio.

## Verification expectations

- web: `npm run build`; for user-facing flows also `npm run test:e2e`.
- backend: `npm test` (20 suites / ~271 tests, ~7 s, fully mocked). The suite mocks `supabaseAdmin` and sets fake env in `api/__tests__/setup.ts`, so no live Supabase is needed.
- Any backend route add/rename/role change **must** be followed by `npm run routes:dump`; `api/__tests__/contract.test.ts` compares the committed `api-contract.json` against the real Express router and fails otherwise.
- landing: `npm run build`.
- No git hooks or CI will catch these for you.

## Backend architecture notes

- Entry `api/index.ts` loads `dotenv` only when `NODE_ENV !== 'production'` (Render injects env), then imports `api/app.ts` (CORS, 1 MB JSON cap, JSON 404/500 handlers).
- Env var is `SUPABASE_SERVICE_KEY`, **not** `SUPABASE_SERVICE_ROLE_KEY`. `api/config/supabase.ts` throws at import time if `SUPABASE_URL`/`SUPABASE_SERVICE_KEY` are missing — tests and scripts must set both.
- Other optional env: `ANTHROPIC_API_KEY` (chat), `SENDGRID_API_KEY` + `SENDGRID_FROM_*` (email; without it invitations silently aren't sent — see `isEmailConfigured`), `WEB_APP_URL` (invite links), `INTERNAL_API_URL`, `CORS_ORIGIN`.
- Request chain: `requireAuth` (Supabase JWT → `req.user`) → `requireTenant` (looks up `users`, sets `req.tenant = { school_id, role, user_id }`) → `requireRole(...roles)`. Tenant tables carry `school_id` (join tables `payment_students`/`student_achievements` inherit it via their parents); filter by it explicitly.
- `requireRole` checks role only, not row ownership. Endpoints taking a `studentId` must go through `api/services/access.ts` `findStudentForTenant` (padre → own children, alumno → own record), or a parent can read another family's data by changing the URL.
- Roles: `super_admin`, `admin`, `profesor`, `padre`, `alumno`.
- AI chat (`api/services/chat/*`, routes under `/api/chat`, admin-only): manual Anthropic loop (`claude-haiku-4-5`, max 15 iterations) that executes tools as internal HTTP calls to this same API, reusing the admin's Bearer token. Sensitive tools (payments, deletes, invitations) pause and require UI confirmation. Response is SSE.
- `backend/scratch/` and `backend/scripts/` are one-off maintenance/import helpers, not part of the app.
- `backend/.env` is tracked in that repo (legacy); do not add new plaintext secrets to it.

## Web notes

- Next.js App Router layout: `app/**/page.tsx` are thin client wrappers that mount a screen and declare its `ProtectedRoute` roles; the real implementations live in `src/screens/`. **Never create `src/pages/`** — Next would treat it as a Pages Router directory.
- `app/(app)/layout.tsx` holds the authenticated shell (`ProtectedRoute` → `AuthGate` → `AppShell`); `app/(auth)/` is the public area. `app/layout.tsx` is the only server component (metadata + CSS) and wraps everything in the client `Providers`.
- Navigation uses `next/navigation` (`useRouter`, `useParams`, `usePathname`) and `next/link`; `<Redirect>` (`src/components/navigation/Redirect.tsx`) replaces React Router's `<Navigate>`. Don't reintroduce `react-router-dom`.
- Everything is client-side on purpose: Supabase session in localStorage, TanStack Query hooks, no SSR data fetching. `src/lib/queryClient.ts` uses no-op storage on the server so the provider tree hydrates identically.
- Browser-only checks (install prompt, iOS detection) must run after mount (`InstallButton` does this); computing them during render causes hydration mismatches that can wipe form input.
- Data access: TanStack Query hooks → `src/api/axios.ts` (JWT interceptor) → Express. Direct Supabase is limited to auth/profile screens and `AuthContext`; do not add direct Supabase queries to hooks.
- Env vars are `NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`; the API falls back to `http://localhost:3000/api`. `next.config.ts` injects `NEXT_PUBLIC_BUILD_ID` on every build to invalidate the persisted query cache.
- PWA is **deferred**: there is no service worker or web manifest in this build. `playwright.pwa.config.ts` and `e2e/pwa.spec.ts` are dormant references for phase 2; don't run or extend them until the PWA is reimplemented.

## Database

- `schema.sql` is the base schema (18 tables incl. `achievements`, `trainings`, `venues`, `teacher_permissions`, `notifications`); `migrations/*.sql` are incremental and dated (`20260511_…`, `20260709_add_chat_tables.sql`). Apply base first, then migrations in filename order, via the Supabase SQL editor — there is no migration runner.
- Docs and schema drift: trust the SQL and controllers over `docs/`.

## Data, scripts, and sensitive material

- `scripts/*.py` are one-off imports/extractions with hardcoded absolute paths and real academy data. Never run them blindly and never commit their outputs; `.gitignore` already blocks the Serratos minor-student data files.
- `mineria/` is the synthetic ML dataset project (`python3 mineria/generar_dataset.py`, stdlib only, fixed seed). Two schools there are invented and flagged `origen = "simulada"` — never present them as real.
- `docs/` has EN/ES pairs (`API-REFERENCE.md`/`REFERENCIA-API.md`, `DATABASE-SCHEMA.md`/`ESQUEMA-BASE-DATOS.md`); update both when changing documentation.
- `CLAUDE.md` is a pointer to this file; keep instructions here only.
